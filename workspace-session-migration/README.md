# workspace-session-migration

把 DSH 的对话从一个工作区迁移到另一个工作区。

DSH 没有内置“移动会话”的操作：每个会话的日志存放在它创建时的工作目录下，会话头里的 `cwd` 决定它属于哪个工作区，而工作区只接受 `cwd` 能解析到自己目录的会话。已有的会话无法直接改写工作目录，所以本插件通过公开的持久化与工作区服务完成迁移：

1. 读取原会话的完整事件日志；
2. 在目标工作区下写一个新会话（标题、创建时间、全部事件与原会话一致，`cwd` 指向目标工作区）；
3. 把新会话挂到目标工作区的会话列表；
4. 把原会话从 DSH 中移除：默认把原日志目录移到备份区；`keepOriginal` 为真时改为归档原会话（仍可通过“取消归档”找回）。

因此新会话的 **Session ID 会变化**——这是 DSH 当前数据模型的限制，不是插件可以绕过的。对话内容、标题、创建时间和事件序号全部保留。

## 安装

插件没有第三方依赖，也不需要构建。任选一种：

- **插件索引 / 添加插件**：在 DSH 的 **插件 → 添加插件** 选择本目录（或通过本仓库的插件索引安装）。
- **仓库开发者**：在 profile 的 shell 里运行

  ```powershell
  node scripts/deploy.mjs --only workspace-session-migration
  ```

安装或更新 Host/Client 模块后需要重启 DSH 才会加载新代码。左侧栏出现「工作区迁移」入口即安装成功。页面需要带 Web 客户端的 profile（Desktop 或 `dsh web`）；没有侧栏的 headless/ACP profile 只加载 Agent 工具。

## 使用

插件提供左侧栏页面和两个 Agent 工具，两者调用同一套迁移逻辑。

### 侧栏页面

1. 左侧栏点击 **工作区迁移**；
2. 选择源工作区和目标工作区（目标目录必须存在；工作区按名称与目录一起显示，同名工作区不会混淆）；
3. 勾选要迁移的会话——打开中、需要格式升级、子代理会话会显示原因并禁用；
4. 先点 **预演** 检查计划，再点 **开始迁移**；
5. 结果区显示新会话 ID、备份位置、跳过和失败原因；迁移后源列表自动刷新。

页面里的 **保留原日志并归档原会话** 对应工具的 `keepOriginal`；默认关闭时原日志移到备份区。

### Agent 工具

在对话里直接让 Agent 调用：

### 1. 先看清单

> 列出所有工作区及其中的会话。

工具 `list_workspace_sessions` 返回工作区 id、标题、目录、目录状态，以及每个会话的 id、标题、创建时间、`cwd`、是否归档/置顶、是否正在打开、是否有日志、格式状态。

### 2. 迁移

> 把 `D:\old\project` 工作区里的这两个会话迁移到 `D:\new\project`：`session-…`、`session-…`。先 dryRun 看一下。

工具 `migrate_workspace_sessions` 的参数：

| 参数 | 必需 | 含义 |
|:--|:--|:--|
| `targetWorkspace` | 是 | 目标工作区的 id 或目录路径 |
| `sessionIds` | 二选一 | 要迁移的会话 id，最多 50 个 |
| `sourceWorkspace` | 二选一 | 该工作区的全部会话都迁移；省略 `sessionIds` 时必需 |
| `keepOriginal` | 否 | 保留原日志并归档原会话；默认 `false`，把原日志移到备份区 |
| `dryRun` | 否 | 只校验并返回计划，不写任何东西 |
| `includeSubagentSessions` | 否 | 同时迁移子代理会话；默认跳过 |

默认（`keepOriginal: false`）会在目标工作区得到一份完整会话，原日志被移到**会话根目录同级的** `session-migration-backups/<时间戳>-<随机串>/<会话 id>/`，可以用文件管理器取回或手动恢复。

原会话的归档与置顶状态会复制到新会话：已归档的对话迁移后仍然归档，不会突然出现在列表里；已置顶的对话保持置顶。

### 跳过和失败

以下会话会被跳过并在结果里给出原因，不会中止其他会话：

- 正在 DSH 中打开的会话（先关闭再迁移）；
- 需要格式升级的会话（先在 DSH 里打开一次，让 DSH 完成升级）；
- 只存在内存中、尚未落盘的会话；
- 子代理会话（除非 `includeSubagentSessions: true`）。

单个会话失败时，插件会尽力回滚：新会话删除、原日志移回原位、工作区归属恢复。

## 限制

- **入口在左侧栏**：页面不是会话右键菜单，也不能从工作区侧栏直接拖拽迁移。
- **Session ID 会变化**：指向旧会话 id 的外部引用（例如手动记下的 id、以会话 id 为键的外部脚本）需要更新。
- **子代理子会话不会自动跟随**：迁移父会话只复制父会话自己的事件；子代理会话仍是独立的会话。
- **源工作区的目录可以不存在**：迁移只读取已保存的会话日志；只有**目标**工作区的目录必须存在。
- **目标工作区的目录必须存在**，否则迁移会被拒绝。
- **备份目录不自动清理**：确认迁移结果后可以自行删除；插件不会删除备份。
- 会话正文只在**本机**读取和写入，不调用模型、不发网络请求、不执行 shell 命令。

## 兼容性

- 已在 DSH `0.2.2-rc.5`（Desktop，Windows）上按当前服务接口实现。
- `engines.dsh` 为 `>=0.2.2-rc.5 <0.3.0`；升级到 0.3 之前需要重新实测。
